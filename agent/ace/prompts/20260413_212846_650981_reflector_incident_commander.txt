# Post-Mortem Report: Redis Crashes and Session Failures

## 1. Root Cause Analysis

**Primary Root Cause**: The Redis container memory limit was configured at only **32 MiB**, which is critically insufficient for Redis operation.

**Contributing Factors**:
1. **Undersized Memory Limits**: The Redis StatefulSet was configured with a memory limit of just 32 MiB. Redis (version 4.0.6) typically requires a minimum of 64-128 MiB for basic operation, with production workloads needing 256 MiB to 1 GiB.

2. **No maxmemory Configuration**: Redis was not configured with a `maxmemory` limit, so it attempts to use all available memory. When Redis exceeded the 32 MiB Kubernetes limit, the kernel's OOM killer terminated the process with OOMKilled status.

3. **Cluster Capacity**: During the fix deployment, the cluster had insufficient CPU resources (only 1 node), causing the pod to remain in Pending state temporarily.

**Timeline**:
- 23:33:52 - Incident started (Redis pods began crashing with OOMKilled)
- 23:38:52 - Investigation began
- ~23:45 - Root cause identified (32 MiB memory limit)
- ~23:50 - Fix applied (updated memory to 512Mi/256Mi)
- ~23:55 - Pod scheduling issue resolved (scaled up node group)
- ~23:56 - Redis pod running successfully

---

## 2. Proposed Fix

The following changes were applied to the Redis StatefulSet:

| Resource | Before | After |
|----------|--------|-------|
| Memory Limit | 32 Mi | **512 Mi** |
| Memory Request | 32 Mi | **256 Mi** |
| CPU Limit | 200m | **500m** |
| CPU Request | 100m | **250m** |

**Additional Actions Taken**:
- Scaled up the application node group from 1 to 2 nodes to ensure sufficient cluster capacity for the increased resource requests.

   - Successfully deployed using the deploy_app tool

**Incident Status**: ✅ **RESOLVED**

The Redis pod crash issue has been successfully resolved by increasing the memory limits from 32 MiB to 512 MiB. The fix maintains the API contract - Redis continues to provide session management and caching services to the user service without any breaking changes.

**Key Learnings**:
- Redis requires significantly more memory than 32 MiB for basic operation
- Default Redis behavior (no maxmemory) conflicts with restrictive Kubernetes memory limits
- Cluster capacity planning is important when adjusting pod resources

**Recommendations**:
1. Consider setting explicit `maxmemory` in Redis config to prevent runaway memory usage
2. Monitor memory usage patterns to find optimal allocation
3. Consider upgrading to a newer Redis version (4.0.6 is from 2017)
