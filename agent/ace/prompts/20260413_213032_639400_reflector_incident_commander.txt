# Post-Mortem Report: Product Listing by Category Returns 404

## Incident Summary
- **Incident:** Product Listing by Category Returns 404
- **Start Time:** 2026-04-12 22:08:18
- **Resolution Time:** 2026-04-12 22:13:18
- **Impact:** Users browsing products by category saw 404 errors instead of product listings

---

## Root Cause Analysis

The investigation identified **two bugs** in `catalogue/server.js`:

### Bug 1: Route Ordering Issue
The Express route definitions were in the wrong order:
- **Line 44**: `app.get('/products', ...)` - Gets all products  
- **Line 83**: `app.get('/products/:cat', ...)` - Gets products by category

Express matches routes in the order they are defined. When a request came to `/products` (get all products), it also matched the pattern `/products/:cat` because "products" was interpreted as the `:cat` parameter. This caused the category query to execute with an invalid category name.

### Bug 2: Inverted Logic
The response logic was inverted (lines 86-90):
```javascript
if(products) {
    res.status(404).send('No products for ' + req.params.cat);  // Wrong! Returns 404 when products ARE found
} else {
    res.json(products);  // Returns empty when nothing found
}
```

The code returned 404 when products were actually found, and returned products when nothing was found - exactly backwards.

---

## Proposed Fix

1. **Reorder routes**: Move the `/products/:cat` route BEFORE the `/products` route so Express correctly matches specific category requests first.

2. **Fix inverted logic**: Swap the if/else blocks:
   - Return `res.json(products)` (200 OK) when products ARE found
   - Return `res.status(404).send(...)` when NO products are found
