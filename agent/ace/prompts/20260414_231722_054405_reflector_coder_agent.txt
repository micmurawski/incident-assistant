## Root Cause Assessment

**The primary issue is the infrastructure (CPU constraints), NOT the code:**

1. The pending pod is due to `200m` CPU limit being too low for the cluster to schedule
2. Even if a pod starts, with only `100m` request / `200m` limit, the single running pod is **throttled to 0.2 cores max**
3. Users experiencing timeouts - likely because the running pod is CPU-starved and can't handle the request load

**Recommendations:**

1. **Increase CPU limits** - at minimum double them: `requests: 200m`, `limits: 500m`
2. The code could be optimized (reduce N+1 queries in `/login`) but it's not the root cause
3. Check cluster node size - if nodes are small, even the 200m limit might not be schedulable
