## Investigation Complete - Root Cause Analysis

Based on my investigation of the cart service and user service source code, here are the specific findings:

### Issues Identified

#### 1. **Cart Service Uses Redis, Not MongoDB**

Looking at `cart/server.js`:
- Uses **Redis** exclusively for cart storage (lines 367-377)
- Cart data is stored with `redisClient.setex()` with a 3600 second TTL
- Uses Redis INCR for anonymous counter tracking

**This finding is critical because:**
- The cart service doesn't depend on MongoDB at all
- The cart functionality should work even if MongoDB is down
- The cart service uses Redis for both data storage AND session ID generation

#### 2. **User Service Has Two Separate Connection Points**

Looking at `user/server.js`:
- **MongoDB connection** (lines 248-274) - connects to `mongodb://mongodb:27017/users`
- **Redis connection** (lines 236-245) - connects to Redis via `redis` hostname

The `/uniqueid` endpoint (lines 48-60) uses **Redis INCR** to generate anonymous user IDs:
```javascript
redisClient.incr('anonymous-counter', (err, r) => {
    res.json({ uuid: 'anonymous-' + r });
});
```

#### 3. **Root Cause of Both Issues - Redis Dependency**

**Both services depend on Redis for session/ID management:**
1. **User service** uses Redis `INCR` for anonymous user IDs at `/uniqueid`
2. **Cart service** uses Redis for all cart operations

If Redis is unavailable after the MongoDB restart (27 minutes ago), both services would fail to:
- Generate new anonymous session IDs
- Add items to carts (even though cart data is in Redis, the cart service may have failed to initialize)

#### 4. **MongoDB Schema/Init Script**

Found `/mongo/users.js` which seeds initial users:
```javascript
db.users.insertMany([
    {name: 'user', password: 'password', email: 'user@me.com'},
    {name: 'stan', password: 'bigbrain', email: 'stan@instana.com'},
    {name: 'partner-57', password: 'worktogether', email: 'howdy@partner.com'}
]);
```

**However**, this isn't run as an initialization script - it's part of the MongoDB container startup.

### Root Cause Summary

| Issue | Root Cause |
|-------|------------|
| Users unable to add items to cart | Cart service requires Redis for cart operations. If Redis became unavailable after MongoDB restart (or was also restarted), cart service cannot initialize properly |
| New anonymous sessions failing | The `/uniqueid` endpoint uses `redisClient.incr()`. If Redis was restarted and lost its state, or is currently unavailable, the INCR operation fails |

### Why MongoDB Restart Caused Problems

The MongoDB restart likely caused a **cascading failure**:
1. When MongoDB restarted ~27 minutes ago, the user service lost database connectivity
2. The user service has retry logic (`mongoLoop()` with 2-second delays), but this doesn't affect Redis
3. However, the **Redis connection** for the user service may have issues because both services share the same Redis instance
4. If Redis was also affected by the restart (even briefly), or if there's a connection initialization issue, both services would fail at startup

### Key Finding: Both Services Need Redis, Not Just MongoDB

The critical insight is that **both issues stem from Redis dependency**, not MongoDB:

- The cart service **ONLY** uses Redis (not MongoDB)
- The user service uses **both** Redis (for session IDs) and MongoDB (for user data)

The MongoDB restart may have been a red herring - checking Redis availability would be more relevant to diagnosing these issues.
