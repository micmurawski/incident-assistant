## Analysis Report: Payment Service Connection Issue

### Summary
After examining the payment service code, I have identified the **root cause** of the connection issues between the payment service and the dispatch service.

### Key Findings

#### 1. **The Connection Model**
The payment service does **NOT** directly connect to the dispatch service. Instead:
- Payment service publishes orders to **RabbitMQ** message queue
- Dispatch service consumes orders from RabbitMQ queue

This is configured in `payment/rabbitmq.py`:
- Exchange: `robot-shop`
- Routing key: `orders`
- Queue: `orders`

#### 2. **The Root Cause - AMQP Host Mismatch**

**Critical Issue Found in `k8s/manifests/payment.yaml` (line 33-34):**
```yaml
- name: AMQP_HOST
  value: rabbitmq-cluster
```

**Problem:** The payment service is configured to connect to `rabbitmq-cluster`, but there is NO Kubernetes service named `rabbitmq-cluster` in the manifests.

**The correct service name from `k8s/manifests/rabbitmq.yaml`:**
```yaml
metadata:
  name: rabbitmq
```

This explains the connection errors:
- **"Connect error"** - The hostname `rabbitmq-cluster` cannot be resolved
- **"169.254.1.1:42699"** - This is the Linkerd proxy's placeholder IP when it can't route to the destination
- **"Connect timed out after 1s"** - Linkerd's default timeout when the endpoint is unreachable

#### 3. **How the Payment Service Connects**

From `payment/rabbitmq.py`:
```python
HOST = os.getenv('AMQP_HOST', 'rabbitmq')
```

- Default fallback is `rabbitmq`
- But Kubernetes override sets it to `rabbitmq-cluster` (non-existent)
- Port 5672 (AMQP standard)

#### 4. **The Dispatch Service**
The dispatch service correctly connects to RabbitMQ using:
```go
amqpUri = fmt.Sprintf("amqp://guest:guest@%s:5672/", amqpHost)
```
Where `amqpHost` defaults to `rabbitmq` (correct name)

### Code Issues Identified

| Issue | Location | Impact |
|-------|----------|--------|
| Wrong AMQP hostname | `k8s/manifests/payment.yaml:34` | Connection failures |
| No retry logic in RabbitMQ publisher | `payment/rabbitmq.py` | Single failure = message lost |
| Hardcoded port in HTTP calls | `payment/payment.py` | Port 8080 hardcoded everywhere |

### Recommended Fix

**In `k8s/manifests/payment.yaml`, change line 34 from:**
```yaml
- name: AMQP_HOST
  value: rabbitmq-cluster
```

**To:**
```yaml
- name: AMQP_HOST
  value: rabbitmq
```

This should resolve the Linkerd proxy errors as the payment service will be able to reach the actual `rabbitmq` service.
