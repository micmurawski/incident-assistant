## Investigation Complete - Root Cause Identified

I've analyzed the catalogue service source code and deployment manifests. Here's what I found:

### 🔍 Analysis

#### 1. Catalogue Service Search Endpoint (`catalogue/server.js` lines 117-129)
```javascript
app.get('/search/:text', (req, res) => {
    if(mongoConnected) {
        collection.find({ '$text': { '$search': req.params.text }}).toArray()...
```
The search endpoint uses MongoDB's **text search** functionality.

#### 2. MongoDB Index Configuration (`mongo/catalogue.js` lines 19-23)
```javascript
// full text index for searching
// db.products.createIndex({
//     name: "text",
//     description: "text"
// });

// unique index for product sku
db.products.createIndex({ sku: 1 }, { unique: true });
```

### 🚨 Root Cause

**The text search index is commented out!** The required MongoDB text index on the `name` and `description` fields has been **disabled**, but the search endpoint still tries to use `$text` queries.

When the `/search/:text` endpoint is called:
1. MongoDB receives a `$text` search query
2. No text index exists on the collection
3. MongoDB throws an error: `text index required for $text query`
4. The error propagates as a **500 Internal Server Error**

#### 3. Deployment Manifest (`k8s/manifests/catalogue.yaml`)
- No issues found - standard configuration
- Service is properly configured on port 8080
- Health check endpoint is properly set up

### ✅ Fix Required

The fix is simple - uncomment the text index creation in `mongo/catalogue.js`:

```javascript
// full text index for searching
db.products.createIndex({
    name: "text",
    description: "text"
});
```

This needs to be applied to the MongoDB database. Either:
1. Re-run the MongoDB initialization script, OR
2. Manually create the index via MongoDB shell/compass
