### Assessment




## Summary of Findings

I've examined the catalogue service code and identified a critical issue causing the 404 errors for the product listing by category API.

### Issue Found

**Route Order Problem (Lines 44 vs 83 in `catalogue/server.js`)**

The route definitions have a critical ordering issue:

1. **Line 44**: `app.get('/products', ...)` - Gets all products
2. **Line 83**: `app.get('/products/:cat', ...)` - Gets products by category

**The Problem**: Express matches routes in the order they are defined. When a request comes in for `/products` (to get all products), it **also** matches the pattern `/products/:cat` because `/products` can be interpreted as a category parameter (`:cat`).

This causes:
- The `req.params.cat` is set to `"products"` (the literal string)
- The MongoDB query searches for products with `categories: "products"` 
- Since no products have that category, it returns the 404 (or empty results)

### Additional Bug

There's also a logic bug in the category endpoint (lines 86-90):

```javascript
if(products) {
    res.status(404).send('No products for ' + req.params.cat);
} else {
    res.json(products);
}
```

This is **inverted**! It returns 404 when products ARE found, and returns products when nothing is found. It should be:

```javascript
if(products && products.length > 0) {
    res.json(products);
} else {
    res.status(404).send('No products for ' + req.params.cat);
}
```

### Recommendations

1. **Fix route ordering**: Move `/products/:cat` route **before** `/products` route, OR rename the category route to something like `/products/category/:cat` to avoid the conflict entirely.

2. **Fix the inverted logic**: Swap the if/else blocks to correctly return products when found, and 404 when not.
