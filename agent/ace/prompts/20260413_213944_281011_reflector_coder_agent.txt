### Root Causes Identified

1. **Artificial delays in code** (lines 146, 173): Each message triggers `time.Sleep(42+rand.Int63n(42))` — that's up to 84ms per order added to existing delays.

2. **Wasted CPU in `processSale()`** (lines 166-171): A pointless checksum calculation loop runs 50,000 iterations per message — pure CPU waste with no purpose.

3. **OpenTracing context errors**: Occur when messages arrive without trace headers (e.g., from external sources, or first message in a new trace). This is actually **expected behavior** logged as an error — not necessarily a bug, but the code logs it which inflates metrics.

4. **Resource limits**: Current limits (80m request, 150m limit) are too low for the CPU spin + delays. The pod is CPU-throttled.

### Recommendations for Fix

**Immediate (code fix):**

1. **Remove artificial delays** — Lines 146 and 173 add 42-84ms latency unnecessarily:
   ```go
   // DELETE this line:
   time.Sleep(time.Duration(42+rand.Int63n(42)) * time.Millisecond)
   ```

2. **Remove the useless checksum loop** in `processSale()` (lines 166-171) — it's pure CPU waste with no side effects.

3. **Fix OpenTracing logging** — The "Failed to get context from headers" is expected for root spans. Change log level from `log.Println` to debug.

**Medium-term (infrastructure):**
