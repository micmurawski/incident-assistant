## Cart Service Memory Leak Investigation Report

### Summary
After reviewing `cart/server.js` (384 lines), I found **one primary memory leak issue** related to the `request` module used for HTTP calls to the catalogue service.

---

### 1. Memory Leak Pattern Identified

#### Issue: Unbounded HTTP Agent connections in the `request` module
**Location:** `cart/server.js` lines 337-351

```javascript
function getProduct(sku) {
    return new Promise((resolve, reject) => {
        request('http://' + catalogueHost + ':8080/product/' + sku, (err, res, body) => {
            // ...
        });
    });
}
```

**Problem:** 
- The `request` module uses the default HTTP/HTTPS agents with `keepAlive: true`
- These agents maintain a persistent connection pool to the catalogue service
- Without explicitly setting `maxSockets` or calling `.destroy()` on the agent after use, connections can accumulate over time
- Each request creates a new socket that may not be properly released if the service is under high load or responding slowly
- This is a **classic Node.js HTTP memory leak pattern** where connection pools grow unbounded

**Called from:**
- `/add/:id/:sku/:qty` endpoint (line 130)
- `/shipping/:id/:zip` endpoint (line 215)

---

### 2. Caching Mechanisms Checked

**Redis (lines 367-377):** Uses `redisClient.setex()` with TTL of 3600 seconds (1 hour). Properly configured - not a leak source.

**Prometheus metrics (lines 11-15):** Counter only - negligible memory impact.

---

### 3. Session/Cart Storage Checked

- Cart data stored in Redis with `setex()` - properly expires after 1 hour
- No in-memory session storage
- No unbounded array growth detected

---

### 4. Other Patterns Checked

| Pattern | Found? | Location |
|---------|--------|----------|
| `setInterval` / `setTimeout` | No | - |
| Event listeners not removed | No | - |
| Growing arrays without cleanup | No | - |
| Closures capturing large objects | No | - |

---

### Conclusion

**Root Cause:** The `request` HTTP client is likely the source of memory growth. When the catalogue service is slow or under load, connections may accumulate in the agent's socket pool without being released, causing memory to grow unbounded until OOM.

**Recommended Fix:** Configure the HTTP agent with bounded socket limits:

```javascript
const http = require('http');

const agent = new http.Agent({
    keepAlive: true,
    maxSockets: 10,        // Limit max sockets per host
    maxFreeSockets: 5,     // Limit free sockets
    timeout: 60000
});

function getProduct(sku) {
    return new Promise((resolve, reject) => {
        request({
            url: 'http://' + catalogueHost + ':8080/product/' + sku,
            agent: agent
        }, (err, res, body) => {
            // ...
        });
    });
}
```
