**Finding:** No OOM kills have occurred. The Redis container has not hit its memory limit.

### 2. Redis Memory Usage vs Limit

| Metric | Value |
|--------|-------|
| **Memory Limit** | **100Mi** (current) ❌ |
| **Current Usage** | ~8.3 MB (7.9 MiB) |

**Analysis:** 
- Current memory usage (8.3 MB) is **well below** the limit (100 Mi)
- The container is only using about **8.3%** of its allocated memory limit
- However, this is misleading - the limit of 100Mi is **too low** per documentation requirements

---

### 3. Redis Maxmemory Configuration

| Check | Result |
|-------|--------|
| **Redis Image** | redis:4.0.6 |
| **Explicit maxmemory config** | Not set in deployment |
| **Default behavior** | Uses all available RAM (no limit) |

**Issue Found:** The Redis deployment does **NOT** have `maxmemory` configured. Without this config:
- Redis will use all available RAM up to the container limit
- When it hits the container limit (100Mi), it may trigger OOM kills
- The old Redis version (4.0.6) may have unexpected behavior with memory limits

---

### 4. Redis Eviction Events

| Check | Result |
|-------|--------|
| **Eviction logs** | None found |
| **Rejected commands** | None found |
| **Recent RDB saves** | Working normally (every 5 minutes) |

**Finding:** No eviction events have occurred yet - likely because the current usage is low.

---

### Critical Issues Identified

| Issue | Severity | Details |
|-------|----------|---------|
| **Memory limit too low** | 🔴 HIGH | 100Mi vs recommended 256Mi minimum |
| **No maxmemory set** | 🔴 HIGH | Redis can consume all container memory, risking OOM |
| **Redis version old** | 🟡 MEDIUM | Using redis:4.0.6 (current is 7.x) |

---

### Root Cause Assessment

The Redis configuration **IS** problematic:

1. **Container memory limit is only 100Mi** - Documentation says it should be **256Mi minimum (not 32Mi)**

2. **No Redis maxmemory configured** - Even with a larger limit, Redis should have `maxmemory` explicitly set to prevent OOM kills

3. **Current low usage is misleading** - The app is only storing ~8MB now, but as traffic grows or session data accumulates, it will hit the 100Mi limit and could cause:
   - OOM kills → Connection failures
   - Session loss → Users get logged out
   - Service degradation → Latency spikes

4. **User service relies on Redis** - As previously noted, session management will fail if Redis pods crash or become unavailable

---

### Recommendation

The Redis memory limit should be increased from **100Mi** to at least **256Mi** (preferably **512Mi**) and `maxmemory` should be explicitly configured via environment variable or command-line argument.
