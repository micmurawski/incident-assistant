### Port Mismatch Confirmed ✅

There is indeed a **port mismatch** between what the catalogue service is trying to connect to and what MongoDB is actually listening on:

- The **catalogue deployment** (line 30 in `catalogue.yaml`) sets: `MONGO_URL=mongodb://mongodb:27018/catalogue`
- The **MongoDB service** (line 52-53 in `mongodb.yaml`) listens on port `27017`

This mismatch would definitely cause connection failures! The catalogue service is trying to connect to port 27018, but the MongoDB service only exposes port 27017.

### Root Cause

The MongoDB container is correctly exposing port 27017 (the standard MongoDB port), and the Kubernetes Service is correctly exposing port 27017. However, the **catalogue service configuration** has an incorrect port (27018) in the `MONGO_URL` environment variable.

### Solution

The fix is simple - change the `MONGO_URL` in the catalogue deployment from:
```
mongodb://mongodb:27018/catalogue
```
to:
```
mongodb://mongodb:27017/catalogue
```

This should resolve the intermittent connection failures the user is experiencing.
